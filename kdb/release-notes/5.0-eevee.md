# Blender 5.0: EEVEE & Viewport


## Breaking Changes

### EEVEE Light Probe Volume Compatibility Breaking

Material `BackFace Culling > Light Probe Volume` property is now working properly. Its meaning was inverted since 4.2. It only affected Light Probe Volume baking.

Older files opened in 5.0 should still result in the same baked lighting. The only exception is for material slot without material assigned which will now bake with the option turned on.

Opening files saved with 5.0 and onward in previous versions of Blender will not result in the same baked lighting.  (blender/blender#147218)

### View Layer Overrides

View Layer Overrides (Material, World, Sample) are now supported. Older files using this feature will render differently. (blender/blender@e16b6ac3da89ef428d0b733d1375ba27cf2f59be)

## Curves
Curve drawing has been rewritten to better support the new Curves object type and all their features.
This comes with small shading improvements in workbench, and makes the geometry closer to Cycles 3D curves.

Be aware that the previously ignored `resolution` curve attribute is now taken into account.
This can make previously working scene run out of memory or severely impact performance, and,
in the most extreme cases, not display certain dense hair system.
For reference, a hair/fur system with default settings in 4.5 will now render 15 times more geometry in 5.0.

As a workaround, the attribute resolution can be manually tuned down and the base curves simplified.

A new "Cylinder" option for curve display type allows to render thicker curves without the flat ribbon appearance.
The new cylinder shape allows for more correct hair shading in workbench and better intersection in EEVEE.  (blender/blender#143180)

EEVEE also now has an internal shadow bias for curves to avoid self shadowing artifact. This can change the appearance of existing files.

## MatCaps

- Added new and reworked the existing viewport MatCaps to include a layer for specular light. This increases shading quality and readability on dark surfaces. (blender/blender@cc04e0128d)

## EEVEE Material Compilation Speed Improvement

Simple materials should now be 4 time faster to compile on NVidia OpenGL driver.
This brings improvement on all backends.

![Compilation Performance Improvement Chart](images/50_compilation_perf.png)

Testing done on with the following hardware configuration:
```
Operating system: Windows-10-10.0.22631-SP0 64 Bits
Graphics card: NVIDIA RTX 6000 Ada Generation NVIDIA Corporation NVIDIA 581.42
```
These timings were captured using the `--profile-gpu` option and do not include EEVEE startup time.
All shader cache were disabled during these tests.

See blender/blender#145347 for a more detailed breakdown.

## Other

- Added `Object > Visibility > Surface Picking` toggle to disable selection, depth picking and surface snapping on half transparent objects. (blender/blender@6b0f57facf8f7ffb887992d41a2251d86b4e7e11)
- HDR and wide gamut are supported on Windows and Linux + Wayland using the Vulkan backend. ([details](color_management.md#hdr-and-wide-gamut-display))
- EEVEE Image Texture node now do not clamp 32 bits HDR values to 16 bits. (blender/blender@4629be1f6c6033d89472fbc8450a12462913cc07)
- EEVEE Light Probe Volume baking has improved baking time, and UI responsiveness. (blender/blender@e5f13a727ab97d906a509f77f31f0e74a1123085)
- EEVEE's engine identifier was changed from `BLENDER_EEVEE_NEXT` to `BLENDER_EEVEE`. (blender/blender@4fe75da973ec74ab4073d3f4d0293428a50ecb55)
- `gtao_distance` has been moved to view layer and renamed to `ambient_occlusion_distance`. (blender/blender@1c29a2e2e5a85f57e27ab2bc9b6b8c24318385bf)
- Workbench/Overlay mesh instancing optimizations (up to 3x fps on scenes with many instances). (blender/blender@8adb3e758f543e87d9e8166c9a2982ed512ac537)

## Bug Fixes

- Auto-depth and other depth aware operators do not ignore unselectable objects anymore. (blender/blender@6b0f57facf8f7ffb887992d41a2251d86b4e7e11)
- When transforming with constraints (e.g. press G to move then X), the axes lines will only show when "Show Overlays" is on. (blender/blender@1df4a09539)
- Viewport Render Image and Animation now support rendering HDR output without clamping. (blender/blender@872c8fb1897d4911d22ae11455c8679a7bf4bea7)
