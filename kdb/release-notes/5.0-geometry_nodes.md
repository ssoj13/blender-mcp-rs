# Blender 5.0: Geometry Nodes

## Bundles

Bundles offer a new way to organize data. A bundle combines multiple values into one, allowing
passing many values with a single link. They are akin to "structs" in programming. (blender/blender@24c4e0a3f796b8a11e648e16ba5682a0effd5f06)

There are three new nodes to work with bundles:

* **Combine Bundle**: Creates a new bundle from the passed in values.
* **Separate Bundle**: Extracts individual values from a bundle.
* **Join Bundle**: Combines multiple bundles into one, also allowing overriding existing values in
  a bundle. (blender/blender@8b3be68b3d358860f2d5757ce61ebf43799bde0c)

Additionally, there is a new *Bundle* socket type that's supported by some other nodes like switch
nodes. New *syncing* functionality simplifies the process of updating nodes based on what is connected.

![New Bundle Nodes](images/bundle_nodes_in_geometry_nodes.png)

Bundles are also available in [Shader Nodes](rendering.md#closures-and-bundles).

For more information, see the [blog post](https://code.blender.org/2025/08/bundles-and-closures/).

## Closures

Previously, when one had to modify the internal behavior of a node group, one always had to edit
the node group itself, limiting reusability. Closures allow injecting additional nodes to evaluate
into a node group. This greatly increases flexibility.
(blender/blender@blender/blender@24c4e0a3f796b8a11e648e16ba5682a0effd5f06)

A new closure is created with the new **Closure Zone**. It is similar to a node group in the sense
that it has inputs and outputs. Additionally, values that are passed in from the outside are
captured and become part of the closure.

The nodes within a closure are executed using the new **Evaluate Closure** node.

![New Closure Nodes](images/closures_in_geometry_nodes.png)

Closures are also available in [Shader Nodes](rendering.md#closures-and-bundles).

For more information, see the [blog post](https://code.blender.org/2025/08/bundles-and-closures/).

## Volumes

Volume grids can now be processed directly with the new grid socket and a set of new nodes. For more information,
read the [blog post](https://code.blender.org/2025/10/volume-grids-in-geometry-nodes/).

![All new volume grid related nodes.](images/geometry_nodes_volume_nodes.png)

- The **Store Named Grid** and **Get Named Grid** nodes are used to get grids in and out of geometries,
  but beyond that, grids are not handled as part of geometries.
- **Mesh to SDF Grid**, **Points to SDF Grid**, and **Mesh to Density Grid** create grids directly from
  other geometry types.
- **Voxelize Grid** and **Prune Grid** adjust the sparseness of grids to allow more control or improve performance.
- **Grid to Mesh** converts the surface of a grid at a specific threshold to a mesh.
- **Field to Grid** creates new grids with field evaluation on the topology of an existing grid.
- **Grid Curl**, **Grid Divergence**, **Grid Laplacian**, and **Grid Gradient** retrieve useful properties
  of grid values.
- **Grid Info**, **Voxel Index**, **Sample Grid**, and **Sample Grid Index** retrieve information directly from grids,
  and **Set Grid Background** and **Set Grid Transform** write data to grids.
- **SDF Grid Boolean** allows boolean operations on grids, similar to the corresponding mesh node.
- A set of filtering nodes process SDF grids (blender/blender@438b8c303e44).
  - **Mean Curvature**: Smoothens high curvature areas more than flatter
  ones.
  - **SDF Grid Laplacian**: Approximates mean curvature flow for true SDFs at lower
  computational cost.
  - **SDF Grid Median**: Reduces noise while preserving sharp features.
  - **SDF Grid Mean**: Fast separable averaging filter for general-purpose
  smoothing with linear computational complexity.
  - **SDF Grid Offset**: Uniform dilation/erosion operation that shifts the SDF
  surface by a world-space distance.
  - **SDF Grid Fillet**: Rounds off concave internal corners by operating only on
  regions with negative principal curvature.
  <video src="../videos/sdf_grid_smoothing.mp4"
        title="Smoothing SDF Grids using OpenVDB operators." width="600" controls=""></video>
- The **Advect Grid** node moves voxel values along a velocity field
  (blender/blender@56bb70fee881).

        title="Advecting a density grid using a velocity field." width="600" controls=""></video>

## Viewer

The viewer node has been updated to support viewing non-geometry data. Additionally, it supports
a dynamic number of input values now. (blender/blender@5ffc5df4f669b705141439c1c8df3b9b36e53bfa)

The <kbd>ctrl+shift+click</kbd> shortcut to connect to the viewer still behaves the same as before.
However, when unlinking something from the viewer, the corresponding socket is automatically
removed.

The spreadsheet supports showing the data of multiple geometries and also supports inspecting the
contents of a bundle.

<video src="../videos/geometry_nodes_viewer.mp4"
        title="Updated Viewer Node" width="600" controls=""></video>

Additionally, the viewer node allows viewing single values directly in the node.

![Single values are shown directly in the viewer node.](images/viewer_node_inline_values.png)

Viewer shortcuts now toggle viewers instead of just enabling them (blender/blender@ac84e076).

## Tangents

There is a new **UV Tangent** node which gives access to tangent vectors on a mesh. By default, the
node outputs tangents created using the [MikkTSpace](http://www.mikktspace.com/) library. Those
tangents are compatible with other places in Blender, especially those used by render engines. (blender/blender@eef9a1b9ae93)

There is also a "Fast" mode which computes tangents ~4x faster but is not compatible with other
parts of Blender. Depending on the use case it might make sense to use that one.

The node requires a UV map on the mesh. This makes the tangents well-defined and also gives control
over the directions.

## Miscellaneous

* New **String to Value** node (blender/blender@ad83a1017f957fb947f3e9aca93b).
* The *Pack UV Islands* node now has a "Shape Method" option (blender/blender@aced349e3dca).
  ![New and updated nodes](images/geometry_nodes_updated_nodes.png)
* Displaying the "Manage" panel in the modifier is now optional. This allows for cleaner looking
  modifiers in cases where this panel is not needed. It can be toggled per modifier and the default
  is set on the node group (blender/blender@fc4fc2d16c11da4e2e9b2c2b458d4e46aabd1f90)
  ![Toggles to change Manage panel visibility](images/show_manage_panel_toggle.png)
* Running a node tool on a mesh no longer removes Shape Key data (blender/blender@33a8b99efcc5).
* Some built-in nodes have menu input sockets now
  (blender/blender@f7f18cd0c74871671e32229c291c9176e9d68f7f,
  blender/blender@76a861ab4156f9aaa3174c1c39c90e4947e22123).
  ![Subset of built-in nodes that have menu inputs now](images/geometry_nodes_menu_inputs.png)
* The *Random Value* node produces better large integers, at the cost of producing different output values compared to before. (blender/blender@513c0494ba4300bd036fa4c1820a2852325b9a8d)
* The shader Gamma node is supported (blender/blender@d803ee4c798bb01251692b378189ad9aa36ec130).
* The color tag is inherited when grouping a single node (blender/blender@24308a9f21e9).
* Attribute text overlays are more readable
  (blender/blender@43fdf067abc926ca9a5d11db1d2038c516437c47).
  ![Text overlay for a color per face corner](images/readable_viewer_text_overlay.png)
* Socket data types are reordered to improve accelerator key assignment and consistency (blender/blender@c010bab779e319336d04140d11b83754497ce08b)
* The `id` attribute is now a generic attribute, while still having some special behavior in a few nodes and for motion blur (blender/blender@ae2034e6c567ddca9233ec6c18d9bcf98bed89c2).
* Improved warning panel title in Geometry Nodes modifier (blender/blender@6614244a69fede4602697472ed6ba46eef40a6b2).
* The viewer node shows a warning when the Geometry Nodes modifier is not evaluated (blender/blender@ea965e0adcd5b0af29ae201c45956e24772c1022).
