# Blender 5.0: Color Management

## Displays and Views

* New Rec.2100-PQ and Rec.2100-HLG displays. May be used for color grading for [HDR video export](pipeline_io.md#images-movies).  (blender/blender!144565)
* New ACES 1.3 and 2.0 views, as an alternative to AgX and Filmic and for compatibility with ACES pipelines. This includes both standard and high dynamic range versions. (blender/blender!144565, blender/blender!146805)
* New AgX HDR view. (blender/blender!142758)

## Working Space

Blend files now have a working color space. The default is Linear Rec.709 as before, with options for Linear Rec.2020 and ACEScg. With these it is possible to use a wider gamut of colors for materials, lights and compositing, and to follow common ACES workflows. (blender/blender!145476)

The working space affects the colors of all data-blocks in a file, and has a significant effect on rendering and compositing results. Generally the working space should be chosen at the start of a project and used for all blend files.

For compatibility, Blender can convert between different working spaces. This is only an approximation and manual fix-ups are often needed.

* In existing blend file, go to Color Management > Working Space to change the working space, with an option to convert the colors.
* For linked blend files, colors will automatically be converted to match the current file.
* For appending assets and other data-blocks, automatic conversion is performed as well.

## HDR and Wide Gamut Display

HDR and wide gamut colors can now be displayed in Blender. (blender/blender!144565)

The display device in the color management panel should be chosen based on the output target.

* When creating a HDR video to be viewed on a HDR TV or YouTube, select either the Rec.2100-PQ or Rec.2100-HLG display. 
* When creating wide gamut images for P3 capable monitors, select Display P3.
* When creating images that can be viewed on all monitors, select sRGB.

### Requirements

* A HDR or wide gamut capable monitor.
* macOS: Any Apple Silicon device.
* Linux: Use Wayland, and set the Vulkan backend in the Blender system preferences. (blender/blender!133159)
* Windows: Enable "Automatically manage color for apps" or "Use HDR" in the Windows display settings, and set the Vulkan backend in the Blender system preferences. (blender/blender!144717, blender/blender!146041)

There are inconsistencies in the HDR implementations in operating systems, browsers and video players. This can make it difficult to reliably preview and export videos with expected colors and brightness. For advanced users, details on the [HDR Brightness](https://projects.blender.org/blender/blender/issues/145855) and [Gamma 2.2 vs sRGB](https://projects.blender.org/blender/blender/issues/145022) implementations may help debug issues.

## OpenColorIO

* Improved compatibility with the OpenColorIO configuration for ACES 2.0. (blender/blender!144565)
* When a blend file is loaded that was created with another OpenColorIO config, a warning is now shown. (blender/blender!145756)
* See the [color management documentation](https://docs.blender.org/manual/en/5.0/render/color_management/opencolorio.html#writing-configurations-for-blender) for how to make a configuration file work well with HDR and wide gamut in Blender.
* New `BLENDER_OCIO` environment variable, that may be used instead of `OCIO` to change the configuration only for Blender. (blender/blender!145882)

## Other

* Images and video can be saved in HDR and wide gamut display color spaces. ([details](pipeline_io.md#images-movies))
* The color picker now has Linear and Perceptual RGB number sliders, to edit RGB values in either the scene linear working space or sRGB. (blender/blender!144564)
* Brush and palette colors are now scene linear, but can still be edited as sRGB in the updated color picker. This makes it easier to match colors with shader nodes, geometry nodes and attributes. (blender/blender!144400)
* New Convert to Display compositor node. For most workflows it is recommended to use the native color management options in the scene and file output nodes. But for some advanced use cases the conversion can be manually performed in the compositor, typically combined with a Raw view transform in the scene. ([details](compositor.md#added), blender/blender!145069)
* New "Working Space" choice in the Convert Color Space compositor node, to convert to and from the current working space that images are in by default. (blender/blender!146598)
* Descriptions of displays, views and color spaces are now show in the user interface. (blender/blender!146339)
