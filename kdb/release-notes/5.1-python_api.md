# Blender 5.1: Python API

## Python 3.13

Python has been upgraded to [version 3.13](https://www.python.org/downloads/release/python-3130/),
matching the [VFX platform 2026](https://vfxplatform.com/).

## Changes

* `mesh.validate()` now fixes invalid (i.e. non-finite)
  Multiresolution tangent vector data when called.
  (blender/blender@b72b204390041a9854bd282ff7f2eb2216e58b47)
* The `columns` parameter of `bpy.types.UILayout.template_list` was deprecated.
  It as in-effective since 5.0. (blender/blender@64de394a08)
* On macOS, scripts and extensions can now access the device camera,
  microphone and system audio. A system permission dialog will be prompted to the user.
  (blender/blender@c1a1748b66a62bcc8f682e9414648348d94aebe8,
  blender/blender@8218d5f5d3c4fec482768b1d2bcf5e5c11bc17e3,
  blender/blender@5b156ec599687396a537433e41b6b125890d70d8)
* Py-defined RNA structs can now fully override their 'name property' (the property used e.g.
  as string key in collections, by UI widgets like search fields, etc.).
  See blender/blender#145682 and blender/blender!149027 for more details.
  (blender/blender@81433ccf01)
* The `sculpt.sample_color` operator has been removed,
  its functionality has been merged into `paint.sample_color`.
  (blender/blender@7178bae1d1befc71108aa25042237d80cfca800c)
* `bpy.app.cachedir` is a new property that returns the cache directory used by Blender
  (blender/blender@e6f3c6a4ac2cd0623417cdc25df93c59b4fe430e).
* A new handler `bpy.app.handler.exit_pre` has been added,
  which allows registering Python code to run when Blender exits.
  (blender/blender@7faeb2a1d1fc0a6367acd3350cec412142445776)
* `UILayout.template_ID_session_uid` is a new template ID search menu which allows
  using ID's session uid as int input values.
  (blender/blender@74956cb715)
* `gpu.types.GPUFrameBuffer.read_color` and `gpu.types.GPUFrameBuffer.read_depth`
  will raise a ValueError when trying to read out of bound
  (blender/blender@3f0450f4d9d6bccb3867dc4fabcae87f3c43c743)
* A number of `Brush` properties related to how the resulting
  stroke will behave have been folded into a single `enum` field,
  `brush.stroke_method`. A list of the old property and the new enum value are as follows
  (blender/blender@29c9353429f4b60c6e4ad234a4d6392a1f513079):
  * `use_airbrush` -> `AIRBRUSH`
  * `use_anchor` ->  `ANCHORED`
  * `use_space` -> `SPACE`
  * `use_line` -> `LINE`
  * `use_curve` -> `CURVE`
  * `use_restore_mesh` -> `DRAG_DOT`
* New functions to find the current scene that is playing (`window.find_playing_scene()`)
  and the window that the playing scene is in (`windows.find_playing()`).
  (blender/blender@347f2c423a1bb22a9aa5e6150e0b605fde1663b4)
* The following Paint stroke operator modes: `SMOOTH`, `ERASE`,
  and `MASK` have been moved from the `mode` property to a new `brush_toggle` property
  (blender/blender@c946d9355b2d7f5288b691c629c71aa601191b8a)

### VSE
- Strip (`strip.`) time properties were renamed to improve clarity and make them easier to remember
  for scripting. Old properties will still be available, but are deprecated (to be removed in 6.0,
  see blender/blender!153012). The full list of renames are as follows:
  * `frame_final_duration` -> `duration`
  * `frame_final_start` -> `left_handle`
  * `frame_final_end` -> `right_handle`
  * `frame_offset_start` -> `left_handle_offset`
  * `frame_offset_end` -> `right_handle_offset`
  * `frame_duration` -> `content_duration`
  * `frame_start` -> `content_start`
  * `animation_offset_start` -> `content_trim_start`
  * `animation_offset_end` -> `content_trim_end`

Note that "content" refers to the underlying source tied to a strip (e.g.
a video file for a movie strip), which may be outside the bounds of the "strip" timeline extents.

- A new `strip.content_end` was added for read-only access to the underlying strip
  content's ending frame (which may be beyond the right handle).
  (blender/blender!153012)
- The `keep_retiming` option for the `sequencer.retiming_segment_speed_set` operator has
  been removed, since segments would only get properly retimed if it was set to `true`.
  Setting its value to `false` merely added unwanted clamping,
  leading to buggy behavior.
  (blender/blender!153509)
