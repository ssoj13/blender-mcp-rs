# Blender 5.0: Animation & Rigging

### Rigging
- A new constraint, **Geometry Attribute**, directly samples vector, quaternion, or 4x4 matrix attributes from geometry and applies these to an object's or bone's transform. (blender/blender@8f41d46d74f51fb5cd6bc55d4af622368a6b6387, [Manual](https://docs.blender.org/manual/en/5.0/animation/constraints/relationship/geometry_attribute.html))
- Bones have two new options in the "Custom Shape" section (blender/blender@b2653be057a86858a3ce9a892189a89278912a91, [Manual](https://docs.blender.org/manual/en/5.0/animation/armatures/bones/properties/display.html#custom-shape)):
  - Affect Gizmo: Places the Gizmo at the location of the Override Transform bone.
  - Use As Pivot: When rotating, the bone will pivot around the origin of the Override Transform Bone.
- Shapekeys have gotten a UI overhaul and additional operators. 
For more details see the [Shapekey section](#shape-keys) below.

#### Working with instances of armatures

In previous versions of Blender it was hard to work with multiple instances of armatures
at the same time. That was because visibility and selection state was shared between them.
This is now separated to address this issue.

- The setting for bone visibility in Object and Pose mode is now stored on the pose bone itself. That means it is possible to hide bones on instanced armatures without affecting the other instances (blender/blender@a43359eb88e898c8e1960564705bf80104b60295).
- The setting for bone selection state is now stored on the pose bone itself. This way the selection is no longer synced across armature instances, making it possible to work with them as expected (blender/blender@a09d0cfd8ccecb57248c6ed96ba25900eab82e0f).

These changes break backwards compatibility for the Python API.
See the [Python](python_api.md#animation-rigging) section for more details.

Any driver on the visibility property is versioned automatically, however animation is not. For that there is an operator "anim.version_bone_hide_property" which copies any F-Curves on that property from the armature to the object for any selected armature object. Note for that to work the object has to have an action and a slot already assigned (blender/blender@699e3344c38cd7b9ebd42a5521e3662e9f2f2cd3).

### Animation
- "Copy Global Transform" is no longer an add-on, but is fully integrated into Blender itself. (blender/blender@b4a8e8c5f8)
- A new "Jump Time by Delta" operator has been added for jumping forward/backward in time by a user-specified delta (specified in either frames or seconds).  The delta is configured with a new popup menu in the animation editor footers (just to the right of the playback buttons), and the jumping itself is done either with the adjacent jump buttons in the footers or with the new Ctrl+Left/Right Arrow shortcuts. (blender/blender@f145e1f7e21620c120ec36e1ef9ac3fe92a098ed)

### Shape Keys

- The list of Shape Keys now supports multi-selection and drag and drop. See [Tree View Improvements](user_interface.md#tree-view) for details.
- New operator: "Make Basis", labeled "Make Shape Key the Basis Key" in the operator search popup
  (blender/blender@301a86d70044f0ac32c6468d42cc45f9956e8439).
  This makes the active shape key the new basis key, effectively applying it to the mesh.
  Previously this was only possible by moving the shape key to the top of the shape key list.
  This is now done via a separate operator, to avoid accidentally applying shape keys.
- The "Join as Shapes" and "Update from Objects" operators have been extended with "Flipped" versions
  equivalent to changing ".L" and ".R" suffixes and running the "Flip" operator afterwards
  (blender/blender@db4d9067d02c9d1654ba33769e576030d221f5f7).
- Shape Keys now support "Copy to Selected" which means that Alt-Drag for editing all selected 
  also works now (blender/blender@614b6508d4fca5dc8892f400fbf1c20231c1430b).  This works well 
  with the new UI Element that Shape Keys are shown in which allows multi select and drag 
  and drop (blender/blender@a559fb833ce86d5bd29eead2dae237da9371e452)

## Backward Compatibility

- Support for loading animation data from Blender 2.49 and older has been removed (blender/blender@6bf86856285015ad468923862cacd3ba33164e16). This support was already limited, as no linking was supported. For migrating files to Blender 5.0, it is recommend to open & save them with Blender 4.5.
- The operators `action.layer_prev` and `action.layer_next` have been removed (blender/blender@19bf803e5152548af7e260088ff1e0679a9ac821). They were already removed from the UI in previous versions.
- Removed the operators to convert a legacy pose library (from Blender 2.93 and older) to the current pose library system (introduced in Blender 3.0) (blender/blender@44913ffb6080f2d99f34031466fe34dc88b3cb2a).
- Since "Copy Global Transform" core add-on was integrated into Blender, any scripts accessing the add-on (trying to enable it, or check if its enabled) will break. Copy and paste operators themselves are still accessible with same IDs, therefore keymaps and scripts calling them will still work. Old add-on properties, which were registered on the scene, are now registered on `scene.tool_settings`.
- Also see the [Python API changes](python_api.md#animation-rigging).
- When creating a driver via Python, it will no longer create an F-Curve modifier but instead create 2 keyframes. (blender/blender@74ea598c085602f61061962c6b62c0d119f64b08)
